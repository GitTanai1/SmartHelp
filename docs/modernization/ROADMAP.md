# SmartHelp Modernization Roadmap

This plan adapts the target architecture to the repository actually audited.
Each increment is independently reviewable; PostgreSQL and React are deferred
until they solve a demonstrated problem rather than being cosmetic rewrites.

| Priority | Current implementation / problem | Proposed change | Affected areas | Dependencies and risks | Acceptance criteria / tests |
| --- | --- | --- | --- | --- | --- |
| P0 | Public CRUD and AI tool endpoints; no tenant/principal | OIDC JWT mode now maps verified email claims to database roles, enforces customer ticket ownership and agent-only mutations, and propagates principals across Java/Python. Add Angular login, tenant migration, and cross-user tests before production enablement. | backend security, users/tickets, AI tools, Angular session | Requires identity-provider/client and tenant migration decision; do not fake a production issuer. | Cross-user and cross-tenant access tests; agent tool cannot exceed caller permissions. |
| P0 | Agent side effects are retriable but not idempotent or auditable | Flyway V1-V3, atomic Java-owned resolution/escalation, idempotency, and append-only application audit events are now present. Add tenant and actor authorization before further agent writes. | database, backend tickets/responses, AI tools | Existing databases must be baselined once; no tenant/principal exists yet. | Duplicate action key returns the current stored result; failed transaction leaves no partial write. |
| P0 | Prompt inputs are not classified as untrusted | ContextBuilder now bounds ticket/retrieval input and response prompts delimit untrusted content. A typed tool registry declares risk, Java permission, timeout, idempotency, and approval requirements, rejecting a high-risk endpoint bypass. Add prompt versioning, document provenance, and a broader adversarial suite. | ai-service graph/prompts/context/tests | Preserve deterministic fallback behavior. | Injection text cannot change tool policy; context composition tests pass. |
| P1 | Layer-first Java packages, no explicit API version | `/api/v1` aliases exist alongside legacy routes. `docs/openapi.json` documents stable v1 ticket, run, approval, and recovery endpoints; Python validates `v1` analysis/SSE events and Spring rejects mismatched ticket or run IDs. | backend, frontend, ai-service, docs | Avoid breaking existing Angular routes; preserve a compatibility period. | Existing CRUD, SSE, and recovery work through the versioned contract; malformed cross-service events fail closed. |
| P1 | MySQL schema scripts drift and production schema init is manual | Introduce Flyway; make one source of schema truth; add transactional boundaries and useful indexes from measured queries. | backend, database, Compose | Requires safe data migration plan. | Clean database migration and integration test succeed. |
| P1 | Fixed graph has no persisted run, budget, cancellation, or approval state | The workflow has finite execution/retry bounds, Java-owned run/event ledger, versioned event validation, response verification, cooperative cancellation, and a `TICKET_RESOLUTION` approval gate. Bounded Python state is atomically checkpointed after each node on a configured persistent volume. | ai-service, backend, frontend | Java remains authority; cancellation does not forcibly interrupt an in-flight model call. Production requires durable checkpoint storage. | Same-run recovery resumes only the next incomplete node; resolution writes require approval; cancelled runs cannot write. |
| P1 | Live-only SSE, cached executor | The executor is bounded, Java persists events, workflows accept a same-run recovery stream, and the Angular explorer can incrementally load events after its last cursor and open a failed run's recovery stream. | backend AI controller, ai-service, frontend | Browser reconnection must preserve event ordering and avoid duplicate rendering. | Reconnect shows prior events, recovery does not replay completed nodes, and cancelled streams release work. |
| P2 | No observability or CI | GitHub Actions, Dependabot, CodeQL, Gitleaks, request IDs, Actuator probes, and basic metrics now exist. Workflow runs retain the originating request ID and expose it in the ticket run explorer. Add structured logs, OpenTelemetry, and cross-service metrics. | all services, `.github` | Telemetry exporter choice/configuration. | A test request carries one trace/request ID across Java and Python; an operator can correlate an agent run to it. |
| P2 | No reproducible evaluation or performance evidence | Versioned deterministic golden/adversarial cases now run in CI. Add report generation, provider-dependent evaluation, and k6 API scenarios. | `evals/`, `load-tests/`, CI | LLM evaluation must separate deterministic checks from provider-dependent runs. | Versioned report comes from checked-in runner; no invented metrics. |
| P3 | Angular application is functional but target mentions React | The existing ticket workspace now includes a persisted run explorer. Decide on a React migration only after OpenAPI-generated types and E2E coverage exist. | frontend or `apps/web` | A full rewrite risks feature regression. | Ticket workflow parity and E2E coverage before retiring Angular. |
| P3 | Portfolio artifacts are sparse | Add ADRs, threat model, runbooks, contribution/security policy, architecture diagram, and measured demo. | docs, README | Claims must link to reproducible evidence. | Reviewer can run documented demo and reproduce stated results. |

## Next increment

Add integration coverage that interrupts a live Python workflow between nodes
and proves Java persists a single terminal business write after recovery. Then
make the browser automatically retry a disconnected recovery stream with a
bounded backoff.
